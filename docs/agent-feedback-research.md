# Agentic SDLC source review: relevance to ChangePlane

Research date: 2026-09-13. Static primary-source inspection; no external agent code, dependencies, model calls or services were executed. ChangePlane baseline: `2d440b7213842934f2cecf9d61cfd48c6e97680d`. Recommendations below are proposed experiments, not measured product improvements.

**Recommendation:** strengthen the existing diagnosis → assigned-writer handback → verified outcome loop, then test whether reviewed feedback improves it. Building another ticket-to-code agent or adding persistent model memory now would expand scope before establishing value.

## Review-agent source inspection

Pinned source: [`Sumanth077/Hands-On-AI-Engineering@c93eec5e3f16f9cee6fe2a30e9516f8a236ffe3f`](https://github.com/Sumanth077/Hands-On-AI-Engineering/tree/c93eec5e3f16f9cee6fe2a30e9516f8a236ffe3f/ai_agents/self_evolving_code_review_agent).

- **Real adaptation, with a narrow meaning.** LangGraph retrieves previous material, asks an Ollama model for structured comments, interrupts for feedback and then distills new insights. Model weights remain unchanged. The graph uses an in-memory checkpointer, so the feedback pause alone is not durable process-restart recovery. [Graph](https://github.com/Sumanth077/Hands-On-AI-Engineering/blob/c93eec5e3f16f9cee6fe2a30e9516f8a236ffe3f/ai_agents/self_evolving_code_review_agent/self_evolving_agent/graph.py)
- **Feedback is not a correctness oracle.** Prompts map acceptance to reinforcement, rejection to avoiding that kind of comment, and editing to refinement. This can learn a convention, but an engineer can reject a valid warning. The model-generated lesson is persisted without a second approval of its generalized meaning. This is a design risk inferred from the flow, not a demonstrated exploit. [Prompts](https://github.com/Sumanth077/Hands-On-AI-Engineering/blob/c93eec5e3f16f9cee6fe2a30e9516f8a236ffe3f/ai_agents/self_evolving_code_review_agent/self_evolving_agent/prompts.py), [graph](https://github.com/Sumanth077/Hands-On-AI-Engineering/blob/c93eec5e3f16f9cee6fe2a30e9516f8a236ffe3f/ai_agents/self_evolving_code_review_agent/self_evolving_agent/graph.py)
- **Stored metadata does not create isolation.** Retrieval searches two shared collections by similarity and a score threshold. Stored scope and confidence are not enforced retrieval filters. The records have no repository, tenant or Git revision binding; there is no rule approval/revocation lifecycle. Reusing this design across unrelated repositories could carry lessons into the wrong context. Persistence includes a diff excerpt, comments and feedback; retry writes generate fresh IDs. [Memory](https://github.com/Sumanth077/Hands-On-AI-Engineering/blob/c93eec5e3f16f9cee6fe2a30e9516f8a236ffe3f/ai_agents/self_evolving_code_review_agent/self_evolving_agent/memory.py)
- **Workflow testing is not efficacy testing.** The subproject contains one test with a fake model and memory, checking interruption and persistence. It contains no held-out bug corpus, recall measurement or before/after correctness experiment. The UI computes rejected comments divided by reviewed comments; zero comments also gives zero rejection. Fewer objections can therefore coexist with missed bugs. The README expressly distinguishes alignment from correctness/security. [Test](https://github.com/Sumanth077/Hands-On-AI-Engineering/blob/c93eec5e3f16f9cee6fe2a30e9516f8a236ffe3f/ai_agents/self_evolving_code_review_agent/tests/test_graph.py), [UI](https://github.com/Sumanth077/Hands-On-AI-Engineering/blob/c93eec5e3f16f9cee6fe2a30e9516f8a236ffe3f/ai_agents/self_evolving_code_review_agent/main.py), [README](https://github.com/Sumanth077/Hands-On-AI-Engineering/blob/c93eec5e3f16f9cee6fe2a30e9516f8a236ffe3f/ai_agents/self_evolving_code_review_agent/README.md)

The useful idea does not require its infrastructure. The example adds Python, Streamlit, LangGraph, local embeddings, Ollama and Actian. Its Docker recipe uses a mutable `latest` image and accepts the database EULA. None is needed to collect operator-owned outcome records for ChangePlane. [Manifest](https://github.com/Sumanth077/Hands-On-AI-Engineering/blob/c93eec5e3f16f9cee6fe2a30e9516f8a236ffe3f/ai_agents/self_evolving_code_review_agent/pyproject.toml), [Docker configuration](https://github.com/Sumanth077/Hands-On-AI-Engineering/blob/c93eec5e3f16f9cee6fe2a30e9516f8a236ffe3f/ai_agents/self_evolving_code_review_agent/docker-compose.yml)

## What to reuse from ExpeL

The [ExpeL paper](https://arxiv.org/abs/2308.10144) studies extracting natural-language knowledge from experience without changing model parameters. Its official repository lists HotpotQA, ALFWorld and WebShop environments. The pinned [evaluation implementation](https://github.com/LeapLabTHU/ExpeL/blob/e41ec9a24823e7b560c561ab191441b56d9bcefc/eval.py) constructs each fold's rule-training IDs by excluding that fold's evaluation IDs. This is the important reusable discipline: evaluate learned guidance on cases it did not learn from. [Official repository](https://github.com/LeapLabTHU/ExpeL/tree/e41ec9a24823e7b560c561ab191441b56d9bcefc)

For ChangePlane, compare the existing runtime with the same runtime plus a frozen, human-reviewed guidance set. Hold the model, source revisions, policy and budgets constant. Separate training incidents from held-out incidents by repository or time; include unknown diagnoses, infrastructure failures, stale evidence, protected paths and misleading review comments. Measure correct diagnosis/action, missed defects, invalid authority outcomes, human rescue time and cost. Keep user acceptance as a separate signal. These are proposed controls, not results reproduced here.

## Fit with the existing product

ChangePlane already binds public assessments to revisions, discards caller-supplied authority, and returns findings plus a handback. Its recovery classifier deliberately leaves generic failed CI as unknown. Team feedback returns untrusted forge references and content digests; its observation path rechecks feedback and revision before handing work back. [Assessment](../community/core.js), [recovery classifier](../src/lib/recovery.js), [review references](../community/team-feedback.js), [team observation](../community/team-github.js)

The smallest useful next step is operator-owned measurement over these records:

1. Record one assessment/incident identity, exact revision and policy digest, diagnosis, operator disposition, next action, observed resolution and human intervention time. Treat these as reported observations, never grants or certifications.
2. Distinguish a useful finding, false finding, duplicate, unclear result and unresolved result. Keep missing outcomes visible; a rejected suggestion must not suppress a deterministic finding.
3. When repeated incidents justify it, propose a short lesson with provenance, applicable repository/path/framework, a counterexample and expiry/review date. Approve it through a repository PR. Revoke or supersede it explicitly. Keep it advisory; it cannot alter protected paths, evidence requirements or controller authority.
4. Consider retrieval infrastructure only after a small file-based reviewed collection demonstrates a held-out benefit. No automatic telemetry, cross-customer lesson sharing or model egress is implied.

KBTG's workflow suggests a possible adopter: a team already generating changes with its own agent and spending time on integration and recovery. It does not establish that this team would buy ChangePlane. A focused pilot should test whether maintainers repeatedly recover real PRs faster using their existing agents, and whether they keep using that path after assisted setup. Ticket ingestion, additional agent roles and a proprietary workspace are not prerequisites for that test.

## Alibaba Open Code Review: a stronger adjacent competitor

Additional source inspected on 2026-09-13: [`alibaba/open-code-review@494bf1c8d7a19196ab166960a06fef38d69a1d16`](https://github.com/alibaba/open-code-review/tree/494bf1c8d7a19196ab166960a06fef38d69a1d16). This is a static assessment of selected modules, not a complete security audit or live integration test.

**Scope and implementation.** OCR is a Go CLI for reviewing workspace changes, commit ranges and whole files. Deterministic file selection and rule resolution surround model-driven context retrieval and review. Its selection function is shared with preview; exclusions have reasons. Comment processing matches snippets to lines, can request model relocation, and uses another model call to filter findings. Deterministic positioning does not make the defect judgment deterministic. Output includes structured comments with paths, line ranges, categories, severities and suggested code. [Selection](https://github.com/alibaba/open-code-review/blob/494bf1c8d7a19196ab166960a06fef38d69a1d16/internal/agent/selection.go), [architecture](https://github.com/alibaba/open-code-review/blob/494bf1c8d7a19196ab166960a06fef38d69a1d16/pages/src/content/docs/en/architecture.md), [comment model](https://github.com/alibaba/open-code-review/blob/494bf1c8d7a19196ab166960a06fef38d69a1d16/internal/model/review.go)

This is substantially beyond the feedback tutorial. The source records coverage and incomplete runs, and resume admission compares repository identity, reviewed input, rule configuration and provider/model transitions. These mechanisms overlap with ChangePlane's concerns. Neither a hybrid architecture nor revision binding should be marketed as a unique invention. [Run manifest](https://github.com/alibaba/open-code-review/blob/494bf1c8d7a19196ab166960a06fef38d69a1d16/internal/session/manifest.go), [resume validation](https://github.com/alibaba/open-code-review/blob/494bf1c8d7a19196ab166960a06fef38d69a1d16/internal/session/resume_identity.go)

**Evidence, not just a demonstration.** Alibaba publishes AACR-Bench and reports comparative precision, recall, F1, time and token results. Its README explicitly acknowledges lower recall while claiming better precision/F1 and approximately one-ninth of the tokens of a general-purpose comparison. These are publisher-reported results, not reproduced here. The website's source contains version-specific result rows, so they must not be attributed automatically to the inspected head or every model. [README](https://github.com/alibaba/open-code-review/blob/494bf1c8d7a19196ab166960a06fef38d69a1d16/README.md), [reported results](https://github.com/alibaba/open-code-review/blob/494bf1c8d7a19196ab166960a06fef38d69a1d16/pages/src/components/BenchmarkSection.tsx)

The [benchmark paper](https://arxiv.org/html/2601.19494v3) describes 200 PRs from 50 repositories across 10 languages, with AI-assisted, human-verified annotations. The [dataset card pinned at `47be1d6`](https://huggingface.co/datasets/Alibaba-Aone/aacr-bench/blob/47be1d6df1e7faf222cf531587772d92f79fe6b2/README.md) describes 2,145 labeled **comments**: 1,505 correct and 640 incorrect, aimed at evaluating review-comment filtering. These counts represent different units. This benchmark supports investigation of review quality; it does not measure recovery time, coordination safety, avoided incidents or ChangePlane's PMF. A fair evaluation must include missed issues and annotation uncertainty, not equate an unreported finding with safe code.

**Deployment and credentials.** There is no mandatory hosted service. OCR requires Git and either a configured model endpoint or a host coding agent in delegation mode. Source dependencies include provider SDKs, MCP, terminal UI and OpenTelemetry libraries; distribution includes platform binaries and an npm launcher. The code is Apache-2.0 licensed. These are useful distribution patterns, not a reason to replace ChangePlane's small Node runtime. [Go dependencies](https://github.com/alibaba/open-code-review/blob/494bf1c8d7a19196ab166960a06fef38d69a1d16/go.mod), [npm package](https://github.com/alibaba/open-code-review/blob/494bf1c8d7a19196ab166960a06fef38d69a1d16/package.json), [license](https://github.com/alibaba/open-code-review/blob/494bf1c8d7a19196ab166960a06fef38d69a1d16/LICENSE), [delegation mode](https://github.com/alibaba/open-code-review/blob/494bf1c8d7a19196ab166960a06fef38d69a1d16/pages/src/content/docs/en/integrations/delegate.md)

The GitHub Action checks out the trusted base, reads head blobs as data and posts comments in a later step. Its example uses `pull_request_target`, a single job with PR-write permission, and mutable `@main` for OCR. Separate steps alone do not establish a separately credentialed controller. An integration into ChangePlane must retain immutable runtime pins, independent authority and fresh-head validation. This is a compatibility boundary, not a demonstrated exploit. [Action](https://github.com/alibaba/open-code-review/blob/494bf1c8d7a19196ab166960a06fef38d69a1d16/action.yml), [workflow example](https://github.com/alibaba/open-code-review/blob/494bf1c8d7a19196ab166960a06fef38d69a1d16/examples/github_actions/ocr-review.yml)

Telemetry defaults to disabled and content logging requires opt-in. Model requests still send selected code/context to the configured provider; local session history is a separate retention surface. Configuration supports stored API keys or a user-authored key-fetch command, so the high-level assurance document's environment-only wording should not be generalized to every current mode. Source and mode-specific documentation are the better authority. [Telemetry defaults](https://github.com/alibaba/open-code-review/blob/494bf1c8d7a19196ab166960a06fef38d69a1d16/internal/telemetry/config.go), [configuration](https://github.com/alibaba/open-code-review/blob/494bf1c8d7a19196ab166960a06fef38d69a1d16/pages/src/content/docs/en/configuration.md), [assurance document](https://github.com/alibaba/open-code-review/blob/494bf1c8d7a19196ab166960a06fef38d69a1d16/ASSURANCE_CASE.md)

**What changes in ChangePlane's plan.** Competing primarily on generating more review comments is a poor next investment. Test whether ChangePlane reduces the work left after an existing reviewer or coding agent has produced findings. A possible later adapter could accept versioned reviewer findings with source revision, tool identity and coverage; missing, partial, stale or malformed data must remain explicit. Such output stays advisory and cannot satisfy Guard, authorize repair or imply merge approval. Validate this with fixtures and a real operator before advertising integration.

For distribution, copy the clarity of one install command, explicit host-agent delegation, sample output and client-specific entry points. OCR's [portable skill guide](https://github.com/alibaba/open-code-review/blob/494bf1c8d7a19196ab166960a06fef38d69a1d16/pages/src/content/docs/en/integrations/agent-skill.md) and public benchmark make the product easier to try and assess. Its [maintainer retrospective](https://github.com/alibaba/open-code-review/blob/494bf1c8d7a19196ab166960a06fef38d69a1d16/pages/src/content/blog/en/oss-two-month-retrospective.md) reports growth from community contributions and internal use; those are self-reported adoption signals, not ChangePlane's demand evidence. Prioritize a repeatable recovery example, externally observed setup friction, repeated weekly use and paid-pilot interest over matching its feature count or publishing unsupported superiority claims.

## GitNexus: structural context for parallel changes

The additional [Facebook post](https://www.facebook.com/photo.php?fbid=1374421598181590&set=a.384790453811381&type=3) is about **GitNexus**, a separate product from Alibaba OCR. Its public text was read without signing in. It describes graph-based impact analysis, call-chain tracing, diff analysis and MCP access. Those are feature descriptions; the post supplies no controlled improvement measurements.

Pinned source: [`abhigyanpatwari/GitNexus@a8736a07d01a0c7109c437ff85425e4cf8e0db06`](https://github.com/abhigyanpatwari/GitNexus/tree/a8736a07d01a0c7109c437ff85425e4cf8e0db06). The CLI indexes code with Tree-sitter and a local LadybugDB graph. Its MCP interface exposes structural context to coding agents. Installation also manages agent configuration and hooks, so adopting it is a real tooling change. The npm manifest includes native parsers, optional embeddings and a Scarf dependency; a local graph does not establish that installation and all connected-model modes have no network activity. No package was installed or executed for this review. [README](https://github.com/abhigyanpatwari/GitNexus/blob/a8736a07d01a0c7109c437ff85425e4cf8e0db06/README.md), [manifest](https://github.com/abhigyanpatwari/GitNexus/blob/a8736a07d01a0c7109c437ff85425e4cf8e0db06/gitnexus/package.json)

**Actual overlap.** `detect_changes` maps Git diff ranges to indexed symbols and affected processes. It validates an explicit worktree against its canonical repository and distinguishes unparsed or degraded results from an empty diff. The backend also carries graph staleness signals; revision freshness and partial-result handling are therefore shared concerns, not unique ChangePlane features. A graph's predicted impact remains evidence about structure, not proof that behavior is correct. [Backend](https://github.com/abhigyanpatwari/GitNexus/blob/a8736a07d01a0c7109c437ff85425e4cf8e0db06/gitnexus/src/mcp/local/local-backend.ts), [freshness](https://github.com/abhigyanpatwari/GitNexus/blob/a8736a07d01a0c7109c437ff85425e4cf8e0db06/gitnexus/src/core/git-staleness.ts)

**Qualification and licensing.** The pinned license and npm manifest identify **PolyForm Noncommercial 1.0.0**. Its permitted-purpose restriction means this is not an unrestricted commercial-use dependency for ChangePlane's individual and business users. Keep any future integration separately operator-selected and qualified; do not vendor it into the Apache-2.0 core or represent its terms as equivalent. The security documentation also identifies different trust boundaries for local and hosted modes. [License](https://github.com/abhigyanpatwari/GitNexus/blob/a8736a07d01a0c7109c437ff85425e4cf8e0db06/LICENSE), [security policy](https://github.com/abhigyanpatwari/GitNexus/blob/a8736a07d01a0c7109c437ff85425e4cf8e0db06/SECURITY.md)

The repository includes an evaluation harness comparing baseline and graph-assisted SWE-bench tasks, with test resolution and cost as metrics. The harness is a useful experimental design, not a result reproduced here or evidence of ChangePlane's effectiveness. [Evaluation guide](https://github.com/abhigyanpatwari/GitNexus/blob/a8736a07d01a0c7109c437ff85425e4cf8e0db06/eval/README.md)

**What changes in our plan.** Path reservations cannot establish semantic independence: one agent can change a producer's return shape while another changes a consumer in a different file. The existing [team summary](../community/team.js) already states that limitation. First collect such incidents and reproduce them with the ordinary test suite. If structural hints improve handback, compare an optional local graph input with the current baseline on held-out cases. Require repository identity, indexed revision, changed-input digest, tool/version, covered languages/files and explicit unknown/partial status. No graph result may widen a task reservation, reduce required CI, grant a writer authority or turn missing dependencies into an all-clear. Recheck the actual combined revision through the forge's existing CI and merge controls. Cross-file recovery is a promising experiment; a new graph engine is not needed to start measuring it.
