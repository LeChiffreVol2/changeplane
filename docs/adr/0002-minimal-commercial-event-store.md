# Add a privacy-preserving commercial event store

**Status:** Candidate design and source for review; no live commercial service or customer activation is established by this ADR.

ChangePlane will add a minimal commercial event store because a repeatable hosted product needs organization entitlement, activation state, usage metering, fleet posture, audit events, reliability measurement, and customer-visible ROI. The store may contain pseudonymous organization, installation, and repository identifiers; plan and entitlement; evaluation state, reason, and latency; activation and audit events; and usage counters. It must never contain source, diffs, prompts, patches, provider responses, credentials, or customer business data.

## Bounded pilot admission

The initial runtime slice admits only operator-enrolled Verify Lite pull-request evaluations under finite Strict Head pilot contracts lasting no more than 30 days. It does not implement the general pricing catalog or automated billing. The trusted server supplies authenticated tenant, repository, Guard installation/App, revision fingerprint and Evaluation Generation; request fields cannot choose an entitlement.

An atomic admission transaction validates enrollment and contract limits, inserts one immutable receipt and increments the tenant's monthly counter once. Exact retries return the same admission. The database assigns the UTC accounting period at admission; late or deleted telemetry cannot revise usage. The server obtains `workflowStartedAt` from the live exact GitHub run attempt bound by OIDC repository, run, attempt, workflow path and event. New admission requires that start time and database admission time to fit the currently active contract window. Caller timestamps cannot substitute, and the immutable receipt preserves the verified start time. An unknown commit may have consumed a unit, so retry resolves the existing receipt without an automatic refund. Completion and recovery reuse admission without consuming another unit or rechecking contract expiry. Admission never authorizes PASS or bypasses current GitHub authority and exact-head checks.

The controller confirms the new `in_progress` Guard and retires prior usable success before any commercial lookup or allowance wait, retaining journal ownership throughout. A denied or unavailable allowance becomes `action_required`; HTTP denial follows acknowledged publication and journal release. Losing the worker during admission leaves a blocking Guard and held lane.

Keep this ledger separate from the earlier event-derived Fleet/usage projection. The runtime may execute checked admission operations and tenant reads, but cannot enroll customers, edit limits, reset counters, refund units or prune receipts. Administrative enrollment changes must first lock the affected tenant contract `FOR UPDATE` and retain that lock through the transaction, so repository changes use the same exclusion boundary as admissions. Manually reviewed invoices are separate; receipt counts alone do not establish charges, value delivered, or gross margin. General outcome ingestion and plan enforcement remain incomplete, and `commercialRuntimeIntegrated` stays false.

## Consequences

The store requires reviewed tenancy, runtime roles, finite metering and cost budgets, incident handling and migrations before customer data is written. Verify forced RLS and actual grants with two tenants, concurrent final-slot admission, retry/unknown-commit recovery, clock boundaries, credential rotation and restore/deletion drills. A tenant database setting is isolation context, not authentication. The proposed hosting region remains subject to provider selection and review; no deployment or data-residency claim is made.

Candidate retention targets are at most 90 days for detailed events and pilot admission receipts, and 13 months for aggregate counters. With contract windows limited to 30 days, a workflow attempt older than a 90-day receipt cannot qualify for fresh admission under any currently active contract, including a renewal. This source rule is the replay boundary after receipt pruning; it relies on trusted GitHub attempt time and database time. Before activation, prove clock handling, contract/enrollment closure, renewal, replay rejection and operator-controlled pruning on the deployed environment. Runtime callers cannot prune or reset accounting. Customer deletion, legal basis and backup handling remain subject to the [approval draft](../retention-deletion.md); no effective deletion deadline is established here.

The separate [Guard publication journal](../guard-publication-journal.md) holds unresolved publication authority and has no automatic expiry. Commercial retention, deletion and restore procedures must not alter that journal or substitute for its durability proof. GitHub remains the source of truth for repositories, revisions, Checks, policy and merge authority.

Fleet Posture, customer-value feedback and complete commercial outcome ingestion remain later surfaces requiring their own authenticated evidence. They are not implied by the bounded pilot admission path.
