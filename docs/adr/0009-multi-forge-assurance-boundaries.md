# Cover multiple forges without collapsing their authority boundaries

The owner expanded ChangePlane's target from GitHub-only PRs to change requests on GitHub, GitLab and Cursor Origin, and accepted multiple tested-subject forms in the 2026-09-10 interview (Q3–Q4). ChangePlane will use a shared assurance and recovery vocabulary while preserving each forge's repository identity, execution provenance, publication authority and native merge-policy semantics. This increases adapter and qualification work, but prevents an authoring tool, mirror, commit status or pipeline summary from being mistaken for an independently authorized assurance result.

## Consequences

This is an accepted product direction, not a declaration of shipped GitLab or native Origin support. The existing GitHub production boundary stays in force until separately reviewed implementation qualifies additional capabilities. The interview's explicit multi-forge direction supersedes the previous GitHub-only product target; it does not relax credential isolation, protected-path review, generation invalidation or deterministic decision authority.

Source-head, test-merge, merge-batch and artifact evidence may be represented, but each requirement must match its actual tested subject and verified relationship to the proposed revision. Policy revision, diff base and target revision remain distinct. Unknown provenance, incomplete observations and unsupported authority remain explicit; accepting an evidence format does not authorize PASS.

Origin-native repositories and GitHub-to-Origin mirrors require different authority bindings. The existing synthetic mirror contract establishes no live Origin qualification. GitLab's pipeline and status mechanisms require their own capability and publisher analysis; the GitHub names Strict Head and Queue Certified do not transfer merely because a pipeline is green.

The shared pure assessment boundary, provider collectors and staged qualification plan are specified as proposals in the [design review](../agentic-sdlc-design-review.md), under the owner-confirmed combined design. Hosted operation remains optional under [ADR-0008](0008-operator-owned-open-source-recovery.md).

The owner selected read-only diagnosis and handback for fork contributions in the next scope (Q9). Trusted policy and collector execution remain separate from fork-controlled code and configuration. Cross-repository patch application is excluded from this milestone. This expands the future read-only support target while preserving the current release's unsupported-fork boundary until qualification passes.
