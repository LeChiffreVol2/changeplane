# Assurance benchmark protocol v1

Maintainer-run exploratory experiment, fixed before the first outcome collection. Not preregistration with an independent registry, a competitive bake-off, or a proof of program correctness. No customer data, model calls, hosted mutations or upstream contributions.

## Population and oracle

Run all 40 Python program suites from QuixBugs commit `4257f44b0ff1181dedaedee6a447e133219fcebf`, both buggy and supplied reference implementations: 80 suites. Keep the upstream tests unchanged, including their two default slow-test skips per variant. Use Python 3.14, the adjacent pinned requirements, a 2-second per-test limit and 60-second per-suite limit identically for both variants. Preserve failure, timeout, infrastructure/unavailable and skip counts; do not discard difficult tasks. Repeat the complete run to test outcome reproducibility; report any disagreement without selecting the better run.

The external oracle is finite upstream test behavior, not inferred from ChangePlane. A timeout establishes noncompletion under the chosen limit, not necessarily a behavioral defect. A passing reference is test-adequate, not proven correct. QuixBugs is a small algorithmic benchmark and does not represent real PR, customer or agent task distributions. The reference programs are supplied solutions, not repairs generated by ChangePlane. No SWE-bench or automated-repair score is computed.

## Experiments and endpoints

1. **Public program execution.** Record 80 candidate outcomes, every collected test outcome, skips, source/test hashes, versions and runtime. The independent unit is a program (40 pairs), not every test invocation.
2. **Production collector replay.** Feed the measured suite conclusions into `community/github.js:inspectPullRequest` through its existing GET-reader seam. Replay unchanged evidence, an old-head success, a head/policy change during collection, wrong publisher/workflow, newer failing/pending reruns, changing reads, protected files, missing pages and provider failure. Also exercise native skipped/neutral policy differences. Persist every outcome and the local API transcript. Transport and event order are synthetic; no GitHub execution or live OAuth claim follows.
3. **Finite observation state enumeration.** Exercise the real `assessObservation` implementation across every combination of head freshness, policy freshness, generation freshness, publisher match, subject match, collection completeness/stability/control-path completeness and protected changes, with success/failure/pending/cancelled/timed-out/skipped/neutral evidence. Compute expected acceptance from the written conjunction below, not from the implementation's decision or reason codes. This is exhaustive only within this finite abstraction, not full protocol model checking or universal safety/liveness proof.
4. **One-constraint ablations.** Import isolated in-memory copies of the observation evaluator with one exact documented source substitution each: head freshness, policy freshness, generation freshness, publisher binding, subject binding, or protected-path evaluation. Fail if the substitution is absent/ambiguous. Never modify production files or deploy weakened evaluators. Retain the first counterexample and count false acceptance/false holds. All ablations are diagnostic; they are not independent products or external baselines.

An observation is eligible only if its head, policy and generation are current; producer and subject match the requirement; collection is complete, stable and control-path complete; no protected path awaits review; and the required execution completed successfully. This oracle describes the public observation contract only, not cryptographic execution provenance, managed Guard, controller mutation, merge approval or campaign enforcement.

## Fair baseline and comparison scope

Use a documented **simulation** of native required-check semantics: exact latest relevant head (or test-merge subject when specified), expected App publisher, latest execution, strict up-to-date base, and success/skipped/neutral accepted. It has the same measured test outcomes and a current authoritative-state view; never compare ChangePlane to a stale-only or any-green baseline. The simulation is not GitHub's implementation or a full rules engine. No deployment or latency superiority claim is allowed.

Only the clean, stale-head and wrong-publisher scenarios are shared comparisons. Newer failed/pending execution rows additionally assume that the current required check corresponds to the newest modeled execution; they are labeled `assumed_current_rerun`, not live-qualified GitHub rerun semantics. Workflow identity, collection consistency, custom protected paths and policy/generation binding are ChangePlane protocol questions; native advanced rulesets/CODEOWNERS may offer related controls, so mark these rows outside the simplified baseline rather than scoring GitHub as wrong. Skipped and neutral are explicit policy differences, never a native safety failure. All other review requirements are assumed already satisfied in the shared scenarios; an observation still grants no merge authority.

The replay keeps the base up to date and does not exercise a test-merge commit; those baseline rules have harness sanity tests only, not experimental qualification. Required job and aggregate workflow outcomes are identical in the shared scenarios; a failed unrelated job with a passing required job is not evaluated. `stale_success` deliberately injects a wrong-revision payload into the head-filtered API seam; it is a robustness case, not a demonstrated live GitHub response. Each row distinguishes measured outcome from effective synthetic evidence, with a full transcript. Unexpected reader/collector exceptions fail the experiment rather than counting as successful rejection; only explicitly declared fault codes become unavailable results.

Report raw denominators, eligible successes, false eligibility, unnecessary holds, unavailable outcomes and authority flags. Enumeration configurations and injected replays are dependent constructed cases, not independent empirical samples. Do not report p-values, population confidence intervals, customer effort saved, model quality, costs saved or independent replication from them. Timing is descriptive local overhead including the supplied-reader harness; it excludes network/CI/model latency and is not a baseline speed contest.

## Reproduction, exclusions and stopping

Pin product source and benchmark driver commit/hashes before collection. Publish original result records, deterministic replay rows, protocol revision and commands. Keep external source outside the product repository with its MIT license and `legal_notes.txt`; do not relicense upstream material. Record any implementation fix and rerun as a new experiment; retain the previous counterexample. A failed invariant or unavailable program suite is an outcome to investigate, not a reason to silently exclude that row. Changes after this protocol freeze must be disclosed.

Before a stronger paper: independent oracle/adapter review, real-forge qualification, larger real-repository benchmarks, a formal model with explicit bounds, and independent reproduction. Live ChatGPT qualification is a separate product task and is not required to execute this offline experiment.
